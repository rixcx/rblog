# デバッグとは
実行中のプログラムを監視し、処理の流れや変数の値を確認して、不具合の原因を調査・修正するための機能。
不具合の原因を探るとは一般的に言いますが、変数に何が入っているか、1行ずつ実行して処理が期待動作に動いているかを確認するのにとても便利なツールです。

# デバッグ環境構築
## 1. launch.json を作成
#### launch.jsonとは
VS Code が「どのプログラムを、どのような設定でデバッグ実行するか」を記述する設定ファイル。今回の場合、**SMAPI をデバッガー付きで起動するための設定ファイル**となります。
プロジェクトルートに`.vscode/launch.json`を作成し、以下を記述します。
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Launch SMAPI",
      "type": "coreclr",
      "request": "launch",
      "program": "C:\\Program Files (x86)\\Steam\\steamapps\\common\\Stardew Valley\\StardewModdingAPI.exe",
      "cwd": "C:\\Program Files (x86)\\Steam\\steamapps\\common\\Stardew Valley",
      "console": "integratedTerminal"
    }
  ]
}
```

## 2. ビルド
デバック設定を反映させるためにビルドをします。
```bash
dotnet build
```

ビルドすると、MODフォルダに PDB（デバッグ情報）が生成されます。
以下の場所に`MyMod.pdb`があることを確認します。
※つくられなくなったかも...？
````txt
C:\Program Files (x86)\Steam\steamapps\common\Stardew Valley\Mods\{Modname}\{Modname}.pdb
````

## 3. デバッグ起動確認
VS Code の左のメニューから`Run and Debug`を開き、
`Launch SMAPI`を選択して`Start Debuging`ボタン（再生ボタンみたいな）をクリック。

ターミナルが開き、Stardew Valleyを起動するときに出るようなログが表示され、Stardew Valleyが起動し、VScodeの下部の色が変わったらOKです🎉


# デバック機能の使い方
メインロジックを以下のように設定してみます。
NPCに話しかけると相手の誕生日をログに出すコードです。
```cs
using System;
using Microsoft.Xna.Framework;
using StardewModdingAPI;
using StardewModdingAPI.Events;
using StardewValley.Menus;
using StardewValley;

namespace DebugTest
{
  internal sealed class ModEntry : Mod
  {
    public override void Entry(IModHelper helper)
    {
      helper.Events.Display.MenuChanged += OnMenuChanged;
    }

    private void OnMenuChanged(object? sender, MenuChangedEventArgs e)
    {
      if (!Context.IsWorldReady)
      {
        return;
      }

      if (e.NewMenu is DialogueBox dialogueBox && dialogueBox.characterDialogue?.speaker != null)
      {
        NPC npc = dialogueBox.characterDialogue.speaker;

        if (npc != null)
        {
          Monitor.Log($"話しかけた相手: {npc.Name}", LogLevel.Info);
          Monitor.Log($"{npc.Name}の誕生日: {npc.Birthday_Season} {npc.Birthday_Day}", LogLevel.Info);
        }
      }
    }
  }
}
```

コードを変えたらビルドすることを忘れずに。


ビルドしたらデバッグモードで起動します。

![](/images/articles/26-08-04/01_toolbar.png?w=300)
ツールバーはこんな感じで、左から以下の通りです。
- Continue: 実行を続ける
- Step over: 次の行へ進む
- Step Into: 関数の中に入る
- Step Out: 関数から抜ける
- Restart: デバッグを再起動する
- Stop: デバッグを停止する

## 1. ブレークポイント
マークを付けたコードまで進むと、処理がストップする機能です。
その時点の変数の入り具合や変化を一つずつ確認することができます。
そこで処理がいったん止まる、ということなので、ゲームも止まります。

以下のコードの左の行数あたりをクリックして赤丸を表示させ、NPCに話しかけてみます。
```cs
NPC npc = dialogueBox.characterDialogue.speaker;
```

ゲームが止まり、左のパネルにvariablesがたくさん出てきました。
その時点で現在定義されている変数などの値が出てきます。

![](/images/articles/26-08-04/02_before.png)

## 2. 変数の確認
デバッグツールの`Step over`を1回クリックすると、`npc[NPC]=null`だったのが`npc = {StardewValley.NPC}`に変わりました。
1の時点ではnullだった`npc`に、`dialogueBox.characterDialogue.speaker`の情報が代入されたためです。

![](/images/articles/26-08-04/02_after.png)

名前は見えていませんが、このときSamに話しかけており、誕生日が`Birthday_Season`と`Birthday_Day`から取得できそうなことがわかります。


## 3. ステップ実行
ブレークポイントで処理を止めた後、`step over`を使うことで、コードを1行ずつ進めながら処理の流れを確認できます。

そのまま処理を進めていくと、コンソールに`Monitor.Log()`の内容が表示されます。
```txt
[DebugTest] 話しかけた相手: Sam
[DebugTest] Samの誕生日: summer 17
```

---

ブレークポイントで止めたコードを進めたい場合は左の`Continue`、
デバッグモードを終わらせたいときは右の`Stop`です。

ツールバーには他にも機能はありますが、ここでは割愛することにします。
